# Prompt Daily Todo 设计

## 目标

在保留现有知识库助手功能的基础上，新增一个独立的 Obsidian 左侧每日计划面板。插件公开 ID 改为 `prompt-daily-todo`，显示名称改为 `Prompt Daily Todo`。每日计划工作流参考 `AI-Daily-Planner` 目录中的规则、任务池、个人配置、复盘记录和 Markdown 模板。

## 范围

### 包含

- 更新 `manifest.json` 的插件 ID、名称和描述；同步更新用户可见文案与 README 中的插件名称。
- 保留现有知识库助手视图、右侧打开行为、规则管理、知识库 AI 整理和每日知识回填。
- 新增每日计划侧边视图，并通过 ribbon 图标与命令打开到左侧 workspace leaf。
- 在设置中新增可配置的每日计划根目录，默认值为 `000ai知识库价值写作体系/AI-Daily-Planner`。
- 读取以下 Vault 相对路径：
  - `01-规划规则.md`
  - `02-参考任务池.md`
  - `03-个人规划配置.md`
  - `04-执行复盘记录.md`
  - `Daily/每日计划文件模版.md`
- 支持日期选择、当天额外约束输入、资料检查、AI 生成、Markdown 预览编辑、重新生成、确认保存和打开今日文件。
- 复用现有自定义 API、Codex、Claude、Gemini、OpenCode 服务商配置与测试机制。
- 生成结果保存前必须经过用户确认；目标文件已存在时禁止覆盖。

### 不包含

- 不自动创建或修改参考资料。
- 不自动上传 Vault 内容；生成前显示资料范围并要求明确确认。
- 不自动修改已确认的每日计划。
- 不实现任务计时器、提醒、后台自动生成或云端同步。

## 用户流程

1. 用户点击每日计划 ribbon 图标或命令，左侧打开每日计划面板。
2. 面板默认选择当天日期，显示工作流目录和五份参考资料的存在状态。
3. 用户可填写当天额外约束并点击“检查资料”。缺少必需资料时禁止生成，并逐项提示缺失路径。
4. 用户点击“生成计划”。插件读取五份资料和额外约束，先展示将发送给 AI 的资料范围，再要求上传确认。
5. AI 返回完整 Markdown。插件检查日期标题和模板核心章节，合格后放入可编辑预览区。
6. 用户可以修改预览内容，或重新生成。重新生成不覆盖已存在文件。
7. 用户点击“确认保存”。插件再次检查目标文件不存在，然后写入 `Daily/YYYY-MM-DD.md`。
8. 保存成功后提供“打开今日计划”操作；若文件已存在，保留原文件并引导用户打开或换日期。

## UI 与视图

新增 `DailyTodoView`，视图类型使用稳定字符串，例如 `prompt-daily-todo-view`。视图内部按职责拆分为：资料状态与日期控制、生成控制、预览编辑、保存结果。沿用当前插件的 `ItemView`、`Setting` 和 Obsidian CSS 变量风格。

每日计划面板的核心控件：

- 日期输入：生成目标日期。
- 额外约束文本框：只作为本次请求输入，不写入参考资料。
- 资料检查按钮与逐项状态。
- 上传确认开关：未确认前不得发送资料。
- 生成、重新生成、确认保存、打开今日计划按钮。
- Markdown 文本编辑区和状态/错误提示。

左侧打开使用 `workspace.getLeftLeaf(false)`，如果已有同类型视图则复用已有 leaf。现有知识库助手继续使用当前右侧 leaf 行为。

## 数据与模块设计

### 设置

在 `KnowledgeBaseSettings` 中新增：

- `dailyPlannerRoot: string`

默认值为 `000ai知识库价值写作体系/AI-Daily-Planner`。路径必须是 Vault 相对路径，读取和保存时拒绝越出 Vault 的路径。

### 每日计划服务

新增服务负责：

- 根据设置根目录和日期解析资料、模板和目标文件路径。
- 批量读取 Markdown 文件并返回缺失/可读状态。
- 生成目标文件名 `Daily/YYYY-MM-DD.md`。
- 检查目标文件是否已存在。
- 通过 Vault API 创建新文件或写入新文件，不执行覆盖。

### AI 请求

保留现有 `AiClient` 服务商路由，增加每日计划专用请求能力；公共传输层继续复用现有 OpenAI-compatible 与本机 CLI 实现。每日计划提示词要求：

- 只能基于提供的资料和额外约束生成计划。
- 输出完整 Markdown，不使用代码围栏或额外解释。
- 遵循参考模板的核心章节、每日上限 4 件、6 小时预算、认知容量 6 单位和风险评估规则。
- 缺少历史记录时不得编造。
- 不声称已经写入文件。

### 响应校验

新增 Markdown 校验器，至少检查：

- 内容非空。
- 包含对应日期的标题 `# 每日 Todo - YYYY-MM-DD`。
- 包含“今日任务”“时间安排”“风险提示”“AI 优化建议”“执行记录”等核心章节。
- 任务数量与关键预算字段可识别；违反硬性限制时阻止保存并显示原因。

## 安全与错误处理

- AI 请求前展示文件路径和内容预览；只有用户明确确认后才发送。
- 不把 API 密钥写入日志、提示词预览或错误信息。
- 所有读取路径限制在 Vault 内，保存路径限制在配置的每日计划根目录内。
- 目标文件存在时返回可操作错误，绝不调用覆盖写入。
- AI 返回无效 Markdown、服务商未配置、资料缺失、读取失败和保存失败均显示 Notice 与面板内状态。
- 所有事件、视图监听器和异步 UI 操作遵循现有插件生命周期清理方式。

## 测试与验证

新增测试覆盖：

- 默认设置和路径解析。
- 缺失资料检测与路径越界拒绝。
- 日期文件名生成和已存在文件保护。
- Markdown 核心章节、日期和硬性约束校验。
- AI 请求包含五份参考资料和额外约束，且不泄露密钥。

