# 本机 CLI AI 服务商设计

## 目标

在保留当前自定义 OpenAI 兼容服务商的基础上，增加 Codex、Claude、Gemini、OpenCode 四个本机命令行服务商。用户可以分别检测命令、发送最小测试请求，并且只有测试成功且返回内容可解析时，才能将该服务商设为当前 AI 服务商。

## 范围与约束

- 插件继续保持桌面端限定，因为本机 CLI 需要 Electron/Node 子进程能力。
- 现有 `AiClient` 接口和 AI 整理、每日回填流程保持不变。
- 现有规则引擎、文件安全检查、预览、人工确认和过期文件保护保持不变。
- 测试请求不读取 Vault 内容、不修改文件、不发送真实文档内容；只验证命令可运行和结果可解析。
- 实际 AI 请求仍然必须经过现有的上传确认。
- 所有子进程通过参数数组启动，不经过 shell 字符串拼接。
- 可执行文件默认使用 PATH 中的 `codex`、`claude`、`gemini`、`opencode`，同时允许用户在设置中填写自定义路径。
- 保持已有设置键兼容；新增设置使用独立字段，不改变已有自定义 API 配置含义。

## 用户体验

设置页的 AI 服务商区域提供五个服务商选项：

1. 自定义 API
2. Codex 本机命令
3. Claude 本机命令
4. Gemini 本机命令
5. OpenCode 本机命令

每个本机服务商显示可执行文件路径、当前检测状态、版本信息、最近测试结果和错误信息，并提供三个动作：

- **检测命令**：运行对应 CLI 的版本命令，确认命令可启动。
- **发送测试请求**：发送固定的最小提示词，要求服务商返回可解析的 JSON 数组。
- **使用此服务商**：仅在最近一次检测和测试均成功后可用；点击后保存当前服务商。

测试失败时显示脱敏后的错误摘要，不显示 API 密钥、完整 Vault 内容或过长的原始输出。

## 架构

### 客户端路由

新增 `AiClientRouter` 实现现有 `AiClient` 接口。面板上下文只持有路由器；每次分析时，路由器根据当前设置创建或复用对应客户端，因此用户在设置页切换服务商后无需重新加载插件。

### 本机 CLI 客户端

新增通用 `LocalCliAiClient`，负责：

- 解析可执行文件配置；
- 使用 `spawn` 和参数数组启动子进程；
- 将 AI 请求提示词通过 stdin 或适配器定义的参数传入；
- 限制超时时间、输出大小和子进程生命周期；
- 分离 stdout/stderr；
- 将非零退出、超时、找不到命令和无效输出转换为统一的 `AiClientError`。

新增 `CliProviderAdapter` 定义每个工具的命令参数、版本参数、请求参数和输出解析方法：

- Codex：非交互 `codex exec`，读取 JSON/JSONL 最终消息。
- Claude：`claude -p`，使用 JSON 输出模式读取最终消息。
- Gemini：`gemini --prompt`，使用 JSON 输出模式读取最终消息。
- OpenCode：`opencode run`，从文本或 JSON 包装输出中提取最终消息。

所有适配器最终都交给现有 AI 建议解析器，要求结果为合法的 `AiSuggestion[]`。适配器不允许直接执行文件修改或让 CLI 执行工具调用。

### 检测与测试状态

新增按服务商保存的运行时状态：`unknown`、`available`、`tested`、`failed`，以及版本、测试时间和脱敏错误信息。状态用于 UI 和“使用此服务商”按钮，不作为持久化凭据。

## 数据流

### 检测

设置页 → 适配器版本命令 → 子进程 → 退出码和版本输出 → 更新服务商状态。

### 最小测试

设置页 → 固定测试请求 → 路由器/适配器 → 本机 CLI → 输出解析 → 验证为合法建议数组 → 更新测试状态。

### 实际分析

AI 整理页或每日回填页 → 当前服务商路由器 → 自定义 HTTP 客户端或本机 CLI 客户端 → 现有建议解析、差异预览和人工确认流程。

## 安全与错误处理

- 不调用 `shell: true`，不把用户输入拼接成 shell 命令。
- 子进程使用当前 Vault 根目录作为工作目录，但 CLI 不被授予自动修改 Vault 的能力。
- 测试请求固定为本地字符串；实际请求仅在 UI 上传确认后构造。
- 设置页限制可执行路径为空、过长或包含换行；错误信息截断并过滤敏感值。
- 超时后终止子进程并清理监听器。
- CLI 输出不是合法建议数组时，保留原始错误类别但不把完整输出写入操作历史。
- 当前服务商测试失效时，禁止继续使用该本机服务商，用户可以切换回自定义 API 或重新测试。

## 测试策略

- 单元测试覆盖四个适配器的版本参数、请求参数和输出解析。
- 子进程运行器使用假的 spawn 工厂测试成功、找不到命令、非零退出、超时、输出过大和取消。
- 路由器测试服务商切换、未测试禁止分析、测试成功后调用正确客户端。
- 设置状态测试确认已有设置可加载，新增字段有默认值，保存后可恢复。
- 运行现有全部测试、构建和 lint。
- 在 Obsidian 中分别检查五个服务商的中文设置界面，并只执行最小测试请求；不执行真实 Vault 内容上传和文件修改。

## 不在本次范围内

- 不实现流式输出。
- 不实现 CLI 会话恢复、历史会话浏览或长期上下文。
- 不让 Codex、Claude、Gemini、OpenCode 直接执行 Vault 文件操作。
- 不增加移动端支持。
- 不修改现有规则文档内容。
